# AI Engine Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working web-chat demo where an AI Engine (safety layer, stage machine, memory, prompt assembly) drives Gemini Flash through an empathetic, personalized GLP-1 dialogue in English.

**Architecture:** Lightweight layered — a pure framework-free engine core (`src/lib/engine/`: safety, stages, cookie codec, prompt assembly, orchestrator) unit-tested with vitest; thin adapters around it (`@google/genai` client, Next.js route handlers); a single-page chat UI on top. Session state travels in an HMAC-signed httpOnly cookie — no database.

**Tech Stack:** Next.js 16.4 (App Router), React 19, Tailwind 4, TypeScript, `@google/genai`, `gemini-flash-latest`, vitest.

**Spec:** `docs/superpowers/specs/2026-10-11-ai-engine-design.md` (the plan argues from the spec; executors read both).

## Global Constraints

- Model: `gemini-flash-latest`, temperature `0.8`, maxOutputTokens `300`, `responseMimeType: "application/json"` with the responseSchema from spec §4.2.
- Turn budgets: `cocreate` must be reachable by turn 8; session max 12 turns then forced `close`; force-advance when the model proposes the same stage for more than 2 turns in a row.
- Stage rules: forward-only, max one stage per turn, minimum 1 turn per stage, `close` only after `cocreate`.
- Memory: max 5 `user_signal` entries, FIFO. Session state < 1KB.
- Cookie: `glp_session`, signed (HMAC-SHA256, secret `SESSION_SECRET`), `HttpOnly; SameSite=Lax; Path=/`.
- Request message: 1–2000 chars after trim; violations → 400, no model call.
- Crisis input: intercepted engine-side; the model is never called for crisis.
- Dialogue copy is English. No medication/dose-change suggestions anywhere in engine output.
- Secrets only in env (`.env.local` / Vercel); only `app/api/*` touches them. Commit `.env.example` with placeholders only.
- Dependencies: add only `@google/genai` (runtime) and `vitest` (dev). No other packages.
- Verification gates before claiming any task done: `npm run lint` (0 errors), `npx tsc --noEmit` (exit 0), `npm run build` (exit 0) at the end of tasks that touch app code.

## Review Focus

Inputs the spec implies but unit tests don't naturally exercise — each pinned to a task below:

1. **First visit, no cookie** — a reasonable person expects a fresh dialogue, not a 500. Pinned in Task 3 (`decodeState(undefined)` → `DEFAULT_STATE`).
2. **Oversized (>2000 chars) or whitespace-only message** — expect 400 before any model call. Pinned in Task 5 (`parseMessage`).
3. **Model returns valid JSON with an unknown stage string or missing fields** — expect one retry, then graceful fallback reply; never a thrown error to the client. Pinned in Task 5 (orchestrator with fake call).
4. **Tampered cookie payload** — expect rejection and a fresh state, not a crash. Pinned in Task 3.
5. **Missing `GEMINI_API_KEY`/`SESSION_SECRET`** — expect a fast, descriptive failure server-side, and a warm canned reply to the client rather than a stack trace. Pinned in Task 5 (call rejection → fallback) and Task 6 (adapter throws descriptive error).

**Interfaces:**
- Consumes: `Stage`, `SessionState`, `ModelOutput`, `DEFAULT_STATE` from Task 1.
- Produces:
  - `function validateTransition(current: Stage, proposed: Stage, stageTurns: number, turn: number): { stage: Stage; forced?: string }` — forward-only, max +1, min 1 turn per stage (a proposed move with `stageTurns < 1` keeps the current stage), `close` rejected unless current is `cocreate`; anti-stall: `stageTurns > 2` → force next stage with `forced: "stalled"`; `turn >= 8 && current !== "cocreate" && current !== "close"` → force advance with `forced: "budget"`.

  - `function appendMemory(state: SessionState, signal: string): SessionState` — trims, skips empty, cap 5 FIFO.
  - `const MAX_TURNS = 12; const COCREATE_DEADLINE = 8; const MEMORY_LIMIT = 5;`

### Task 5: Orchestrator — wiring with a fake model call

**Files:**
- Create: `src/lib/engine/orchestrator.ts`
- Test: `src/lib/engine/orchestrator.test.ts`

**Interfaces:**
- Consumes: everything from Tasks 1–4.
- Produces:
  - `type GeminiCall = { json(system: string, message: string): Promise<unknown>; text(system: string, message: string): Promise<string> }` — what Task 6 implements and the UI-agnostic core depends on.
  - `function parseModelOutput(raw: unknown): ModelOutput | null` — strict shape check: `reply` non-empty string; `stage` one of the five; `user_signal` string (may be empty).
  - `function parseMessage(body: unknown): { ok: true; message: string } | { ok: false }` — object with string `message`, trimmed length 1–2000.
  - `function handleMessage(deps: { call: GeminiCall; secret: string }, message: string, state: SessionState): Promise<{ reply: string; state: SessionState }>`:
    1. `assessSafety` on the message; crisis → return `CRISIS_REPLY` with unchanged state (model never called).
    2. Set `depressionConcern` on the state copy when flagged.
    3. Build system instruction; `deps.call.json`; `parseModelOutput`; if null → one retry; if still null → `deps.call.text` → reply = that text with stage from heuristics (`validateTransition` keeping current stage; anti-stall still applies); if the text call throws → `FALLBACK_REPLY` + heuristic advance.
    4. `applyModelOutput` → new state; `turn >= 12` → state forced to `close` stage with `forced: "session-end"`.
    5. Return `{ reply, state }` (crisis/fallback paths return their fixed replies).

- [ ] **Step 1: Write failing tests** with an inline fake `GeminiCall` (recording calls, returning canned values):
  - crisis message → reply is `CRISIS_REPLY`, fake not called, state unchanged except nothing.
  - depression message → returned state has `depressionConcern: true`.
  - happy path: fake returns valid output → reply passes through, state stage/turn advanced, memory appended, exactly one `json` call.
  - fake returns `{ reply: 42 }` then valid output on 2nd call → two `json` calls, valid reply used.
  - fake always invalid → `text` called once, its reply used; `text` throws → `FALLBACK_REPLY`, no exception escapes.
  - `parseMessage`: `{ message: "  hi  " }` → ok `"hi"`; 2001 chars → not ok; whitespace-only → not ok; non-object → not ok.
  - turn 12 reached → state stage `close`.
- [ ] **Step 2: Verify RED.**
- [ ] **Step 3: Implement** `parseModelOutput`, `parseMessage`, `handleMessage` (retry/fallback as above; no mocks inside the module — the fake comes from tests).
- [ ] **Step 4: Verify GREEN** — `npx vitest run`.

Model failure surfaces as the orchestrator's canned reply (never a 500 body with a stack trace). Missing `SESSION_SECRET` → module-level descriptive throw.

  - `.env.example` — `GEMINI_API_KEY=your_key_here`, `SESSION_SECRET=generate_a_long_random_string`.
